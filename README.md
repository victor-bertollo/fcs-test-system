# FCS Test System

Проект предназначен для автоматической проверки цифровых микросхем и собранных макетных схем.

Используются две готовые проверочные платформы:

1. **Платформа для микросхем** — на ней расположен слот для проверяемого чипа.
2. **Платформа для макеток** — из неё выходят два набора проводов:
   - `DRIVER` подключаются ко входам проверяемой макетки;
   - `RECEIVER` подключаются к выходам проверяемой макетки.

## Что понадобится

- компьютер с Windows, macOS или Linux;
- Git;
- Python 3.10 или новее;
- одна из двух проверочных платформ;
- USB-кабель с поддержкой передачи данных;
- проверяемая микросхема или макетка.

## 1. Скачивание проекта

Откройте терминал и выполните:

```bash
git clone https://github.com/victor-bertollo/fcs-test-system.git
cd fcs-test-system
```

Все дальнейшие команды выполняются из каталога `fcs-test-system`.

## 2. Подготовка Python

Создайте отдельное виртуальное окружение `.venv` и установите зависимости.

### Windows PowerShell

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### macOS и Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

После активации в начале строки терминала обычно появляется `(.venv)`.

При следующих запусках заново создавать окружение и устанавливать библиотеки не нужно. Перейдите в каталог проекта и активируйте существующую `.venv`:

```bash
# macOS и Linux
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

## 3. Подключение платформы к компьютеру

1. Подключите USB-кабель к ESP32 на проверочной платформе.
2. Подключите второй конец кабеля к компьютеру.
3. Подождите несколько секунд, пока компьютер определит устройство.
4. Найдите появившийся последовательный порт.

USB-кабель должен поддерживать передачу данных. Кабель только для зарядки не подойдёт.

### Windows

Откройте **Диспетчер устройств → Порты (COM и LPT)**. Нужный порт выглядит как `COM3`, `COM4` и т. п.

Если порт непонятен, отключите платформу, посмотрите список, затем подключите её снова. Новый порт относится к ESP32.

### macOS

```bash
ls /dev/cu.*
```

Обычно порт выглядит как `/dev/cu.usbmodem...` или `/dev/cu.usbserial-...`.

### Linux

```bash
ls /dev/ttyACM* /dev/ttyUSB*
```

Обычно порт выглядит как `/dev/ttyACM0` или `/dev/ttyUSB0`.

При ошибке `Permission denied` добавьте пользователя в группу `dialout`, затем выйдите из системы и войдите снова:

```bash
sudo usermod -aG dialout "$USER"
```

## Проверка отдельной микросхемы

### 1. Установите чип

1. Отключите платформу от USB.
2. Найдите на микросхеме ключ — выемку или точку около первого вывода.
3. Совместите ключ с обозначением на слоте платформы.
4. Аккуратно вставьте микросхему. Все ножки должны попасть в контакты и не загнуться.
5. Подключите платформу к компьютеру по USB.

Не устанавливайте и не извлекайте микросхему при подключённом питании.

### 2. Выберите тест

Готовые тесты находятся в каталоге `new_chip_tester/configs`:

| Файл | Микросхема | Назначение |
| --- | --- | --- |
| `not.yaml` | 74HC04 | инверторы NOT |
| `and.yaml` | 74HC08 | элементы AND |
| `or.yaml` | 74HC32 | элементы OR |
| `xor.yaml` | 74HC86 | элементы XOR |
| `add.yaml` | 74HC283 | 4-битный сумматор |
| `demux.yaml` | 74HC139 | дешифратор/демультиплексор |
| `mux.yaml` | 74HC157 | мультиплексор |
| `cnt.yaml` | 74HC161 | 4-битный счётчик |

Выбирайте файл по маркировке на корпусе чипа. Например, для `74HC04` нужен `not.yaml`.

### 3. Запустите тест

Общий вид команды:

```text
python new_chip_tester/chip_tester.py ПУТЬ_К_YAML --port ПОРТ
```

Windows:

```powershell
python new_chip_tester/chip_tester.py new_chip_tester/configs/not.yaml --port COM3
```

macOS:

```bash
python new_chip_tester/chip_tester.py new_chip_tester/configs/not.yaml --port /dev/cu.usbmodem1101
```

Linux:

```bash
python new_chip_tester/chip_tester.py new_chip_tester/configs/not.yaml --port /dev/ttyACM0
```

Чтобы увидеть результат каждого шага, добавьте `--show-passes`:

```bash
python new_chip_tester/chip_tester.py new_chip_tester/configs/not.yaml --port /dev/ttyACM0 --show-passes
```

## Проверка собранной макетки

На второй платформе есть два набора пронумерованных проводов:

- `DRIVER` подают тестовые сигналы;
- `RECEIVER` считывают выходные сигналы.

Номер провода важен: `DRIVER 1` соответствует первому входному сигналу теста, а `RECEIVER 1` — первому проверяемому выходному сигналу.

### 1. Подключите макетку

1. Отключите проверочную платформу от USB.
2. Определите входы и выходы проверяемой макетки.
3. Подключите провода `DRIVER` только ко входам макетки.
4. Подключите провода `RECEIVER` только к выходам макетки.
5. Проверьте соответствие номеров проводов выбранному тесту.
6. Если макетке нужно отдельное питание, подключите его по её схеме и объедините землю макетки с землёй проверочной платформы.
7. Проверьте соединения и подключите платформу к компьютеру по USB.

> Не подключайте `DRIVER` к выходу макетки. Если выход макетки и платформа одновременно установят разные уровни, оборудование может быть повреждено.

### 2. Выберите тест

Готовые тесты находятся в каталоге `maket_tester/configs`:

- `multiplier_4x4.yaml` — полная проверка 4-битного беззнакового умножителя;
- `first_8_pins_sweep.yaml` — перебор комбинаций на первых восьми `DRIVER` для проверки подключения и наблюдения за выходами.

Для `multiplier_4x4.yaml` подключите:

- восемь входов макетки к `DRIVER 1`–`DRIVER 8`;
- восемь выходов результата к `RECEIVER 1`–`RECEIVER 8`.

Порядок битов должен соответствовать порядку сигналов в вашей схеме и YAML-файле. Если результат постоянно неверный, в первую очередь проверьте, не перепутаны ли младшие и старшие биты.

### 3. Запустите тест

Общий вид команды:

```text
python maket_tester/maket_tester.py ПУТЬ_К_YAML --port ПОРТ
```

Linux:

```bash
python maket_tester/maket_tester.py maket_tester/configs/multiplier_4x4.yaml --port /dev/ttyACM0
```

Windows:

```powershell
python maket_tester/maket_tester.py maket_tester/configs/multiplier_4x4.yaml --port COM3
```

macOS:

```bash
python maket_tester/maket_tester.py maket_tester/configs/multiplier_4x4.yaml --port /dev/cu.usbmodem1101
```

Для вывода каждого успешного шага добавьте `--show-passes`.

`first_8_pins_sweep.yaml` не проверяет выходы по таблице правильных значений. Он предназначен для ручного наблюдения и первичной проверки подключения:

```bash
python maket_tester/maket_tester.py maket_tester/configs/first_8_pins_sweep.yaml --port /dev/ttyACM0 --raw --show-passes
```

## Как понимать результат

### Успешная проверка

Для микросхемы:

```text
RESULT 74HC04 NOT: PASS (64 tests)

GLOBAL SUMMARY
not.yaml         : PASS

VERDICT: CHIP MATCHES not
```

Для макетки:

```text
RESULT 4x4_unsigned_multiplier: PASS (256 tests)

GLOBAL SUMMARY
multiplier_4x4.yaml      : PASS

VERDICT: BOARD PASSED
```

`PASS` означает, что все проверенные выходные сигналы совпали с ожидаемыми.

### Ошибка

```text
FAIL 0003: inputs=000010
  frame    = 0z1z0zgzzz0z0z0v
  read     = 0101010001010100
  expected = p2=1 p4=0
  errors   = pin 4: expected 0, got 1
```

Здесь:

- `FAIL 0003` — ошибка возникла на третьем тестовом наборе;
- `frame` — сигналы, поданные платформой;
- `read` — фактически считанные сигналы;
- `expected` — ожидаемые значения;
- `pin 4: expected 0, got 1` — на линии 4 ожидался `0`, но был получен `1`.

Возможные причины `FAIL`:

- микросхема или макетка неисправна;
- микросхема вставлена неверной стороной;
- провод подключён не к тому контакту;
- перепутаны `DRIVER` и `RECEIVER`;
- перепутан порядок битов;
- отсутствует питание или общая земля;
- провод плохо держится в макетке;
- выбран YAML-файл от другого устройства.

Итоговые сообщения:

- `PASS` — проверка пройдена;
- `FAIL` — найдено несовпадение или возникла ошибка связи;
- `BOARD PASSED` — макетка прошла все тесты;
- `BOARD FAILED` — макетка не прошла тест;
- `NO CONFIG PASSED` — ни одна конфигурация не подошла;
- `AMBIGUOUS` — успешно прошли несколько конфигураций.

После `FAIL` сначала отключите USB-питание, затем проверяйте ориентацию чипа и провода.

## Как устроен YAML-тест макетки

Тесты макеток описываются в YAML-файлах следующего вида:

```yaml
board: example
stop_on_fail: true
reset_before_run: true

tests:
  - name: first case
    frame: "0100zzzzzzzzzzzz"
    expect: "001xxxxxxxxxxxxx"
```

`frame` содержит 16 символов — по одному для каждого `DRIVER`:

| Символ | Действие |
| --- | --- |
| `0` | подать логический ноль |
| `1` | подать логическую единицу |
| `z` | перевести линию в Z-состояние |
| `c` | подать тактовый импульс |
| `v` | подать высокий уровень |
| `g` | подать низкий уровень |

Первый символ относится к `DRIVER 1`, последний — к `DRIVER 16`.

`expect` содержит 16 символов — по одному для каждого `RECEIVER`:

| Символ | Ожидаемое значение |
| --- | --- |
| `0` | логический ноль |
| `1` | логическая единица |
| `x` | значение не проверяется |

Первый символ относится к `RECEIVER 1`, последний — к `RECEIVER 16`.

Перед запуском нового теста внимательно проверьте каждый символ `frame`: он определяет уровень на соответствующем входе макетки.

## Полезные параметры

Полная справка:

```bash
python new_chip_tester/chip_tester.py --help
python maket_tester/maket_tester.py --help
```

| Параметр | Назначение |
| --- | --- |
| `--port` | порт подключённой платформы |
| `--show-passes` | показать каждый успешный тест |
| `--raw` | показать обмен данными с платформой |
| `--timeout` | изменить время ожидания ответа |

Обычно достаточно указать YAML-файл и `--port`.

## Частые проблемы

### Не найден модуль `serial` или `yaml`

Активируйте `.venv` и установите зависимости:

```bash
python -m pip install -r requirements.txt
```

### Порт не найден

- проверьте, что USB-кабель поддерживает данные;
- отключите и снова подключите платформу;
- повторно найдите имя порта;
- попробуйте другой USB-порт компьютера.

### Порт занят

Закройте Arduino Serial Monitor, терминальные программы и другие приложения, которые могут использовать ESP32.

### Платформа не отвечает

- убедитесь, что подключена нужная проверочная платформа;
- проверьте имя порта;
- переподключите USB-кабель;
- повторите команду с `--raw`;
- при необходимости увеличьте тайм-аут.

Пример:

```bash
python maket_tester/maket_tester.py maket_tester/configs/multiplier_4x4.yaml --port /dev/ttyACM0 --timeout 1.0 --raw
```

### Тест остановился после первого `FAIL`

Остановкой управляет флаг `stop_on_fail` в выбранном YAML-файле.

Чтобы остановить проверку после первой ошибки:

```yaml
stop_on_fail: true
```

Чтобы выполнить все тестовые наборы и увидеть все ошибки:

```yaml
stop_on_fail: false
```

После изменения сохраните YAML-файл и запустите тест повторно.

## Краткая памятка

### Микросхема

1. Отключить USB.
2. Правильно вставить чип в слот.
3. Подключить USB к ESP32.
4. Активировать `.venv` и найти порт.
5. Запустить `new_chip_tester/chip_tester.py` с YAML нужного чипа.
6. Проверить `PASS` или изучить строки `FAIL`.

### Макетка

1. Отключить USB.
2. Подключить `DRIVER` ко входам макетки.
3. Подключить `RECEIVER` к выходам макетки.
4. Проверить номера проводов, питание и общую землю.
5. Подключить USB к ESP32.
6. Активировать `.venv` и найти порт.
7. Запустить `maket_tester/maket_tester.py` с нужным YAML.
8. Проверить `PASS` или исправить указанные в `FAIL` линии.
